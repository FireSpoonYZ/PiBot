# 跨设备原生剪贴板同步（Clipboard Sync）

在「设置 → 剪贴板同步」将需要互通的设备加入同一组，并分别开启本机开关。一端复制后，其他在线成员的系统剪贴板自动更新；到目标应用正常粘贴即可。

## 交互模型与前置条件

- **一次入组 + 单设备开关**：所有需要互通的已配对设备共享同一串组码（`pibot-clipboard-v1:<43位无填充base64url>`，内含 256-bit OS 随机组密钥），支持新建组、输入组码加入既有组、查看当前组码；每台设备各自维护一个独立总开关。关闭开关立即断开剪贴板链路并停止收发，且开关与组码严格绑定当前 Center（origin + deviceId + 凭据指纹），切换或重新配对 Center 时不跨中心迁移。
- **Center 升级要求**：剪贴板同步复用 Center 既有 `/v1/link` HTTPS/WSS 监听，通过显式 Upgrade 头 `X-PiBot-Clipboard-V1: 1` 分流到独立的 `WebSocketServer`（与 Host / Control / LIVE / Scope 完全隔离）。旧版 Center 不识别该分流头，必须先将 Center（Docker 镜像或 DEB 包）升级至包含 `host-core/clipboard-relay.js` 的版本；反向代理无需新增路径，继续透传 `/v1/link` 的 WebSocket Upgrade 即可。
- **仅实时在线同步**：中继**不保存成员关系、不持久化载荷、无离线积压、无重放**。仅当发送瞬间双方均已配对、已开启开关、加入同一组且在线时才会投递；离线期间复制的内容不会补发，新加入或重连设备不会收到之前的剪贴板内容。Center 吊销设备或轮换令牌后，中继立即并在 1 秒周期复核中踢断连接（关闭码 `4403` / `4401`）。

## 端到端加密与安全边界

- **端到端加密**：组密钥经 HKDF-SHA256 派生出互不相同的 256-bit `XChaCha20-Poly1305` AEAD 密钥与 64 字符的小写十六进制 `clipboardGroup` 路由 ID。Center 只看到已认证的 `deviceId`、路由 ID、24 字节随机 `nonce`、密文与 `sentAt`（UTC 秒），无法读取明文或组密钥。AAD 显式绑定协议版本、`sender_id` 与 `sent_at`；接收端强制 `±30 s` 时钟窗并用有界内存 `ReplayCache`（默认容量 1024，满时 fail-closed）拦截 `(fromDeviceId, nonce)` 重放。
- **仅纯文本 / 64 KiB 上限**：仅同步非空 UTF-8 纯文本，最大 **64 KiB**（`65,536` 字节），拒绝 NUL 字节且不做有损转码或规范化。中继侧约束单帧 `≤ 96 KiB`、单连接待发送缓冲高水位 `256 KiB`、速率 `16 次 / 10 s`、单组最多 `16` 台在线设备、总连接上限 `128`（待握手 `32`）。
- **连续复制与入组状态**：客户端发送间隔至少 650 ms，只保留最新待发文本；断线、关开关和换组会丢弃待发项。中继丢弃超限更新，不断开发送设备。组满或被同一设备身份的另一连接替换时，客户端给出具体原因，处理后可关闭再开启本机同步。
- **敏感标记（best-effort）与防泄露硬规则**：
  - 各平台尽量跳过来源应用声明的敏感/隐藏剪贴板，但该能力依赖密码管理器或系统正确附带标记，属于尽力保护（best-effort），不能保证拦截所有未打标口令。
  - **硬拦截 PiBot 码**：核心资格检查（`eligible_text`）永久拒绝独立或嵌入包含 PiBot 设备配对码前缀 `pibot1.` 或剪贴板组码前缀 `pibot-clipboard-v1:` 的任意文本，绝不自动或手动同步到其他设备。
  - **禁止明文进入 WebView/日志/持久化**：原生层不打印、不落盘剪贴板明文与组密钥；Android 组码与开关保存在不参与系统备份的独立加密文件，WebView 仅调用固定动作名，不接收剪贴板正文。
- **明确排除范围（Non-Goals）**：
  - 不提供剪贴板历史、云端缓存或离线队列；
  - 不同步文件、图片、HTML/富文本、URI 或 Intent；
  - 不做自动粘贴、键盘模拟或窗口剪贴板注入（只写入系统剪贴板）；
  - 不向 Bot、Host 工具、Webhook 或 Center MCP 暴露剪贴板读写、组码或开关能力。

## 平台语义与限制

### 桌面端（Windows / Linux；暂不含 macOS）

- **托盘与进程语义**：同步由桌面客户端承担，不是 `pibot-host` 的后台功能。同步已开启、且系统可用托盘时，关闭主窗口会退到托盘，继续同步。托盘显示连接状态，可以暂停或恢复与设置页共用的本机开关。通过托盘暂停时图标保留；在设置页关闭同步会移除托盘。退出客户端会停止同步，不停止 Host，也不会主动清空系统剪贴板；Linux 上如果没有独立剪贴板管理器，进程退出时 PiBot 持有的文本可能不再可粘贴。不添加登录自启；没有可用托盘时沿用原来的关窗行为。
- **无焦点抢占**：Windows 在独立工作线程使用不可见 `HWND_MESSAGE` 窗口与 `AddClipboardFormatListener` / `WM_CLIPBOARDUPDATE`；Linux Wayland 走无表面 `ext-data-control` / `wlr-data-control`，X11 走独立连接与未映射 `InputOnly` 窗口 + `XFixes`。
- **Windows 过滤与防回环**：仅读取 `CF_UNICODETEXT`，直接跳过 `CF_HDROP`（文件复制）以及 `ExcludeClipboardContentFromMonitorProcessing`、`CanIncludeInClipboardHistory`、`CanUploadToCloudClipboard` 标记；写入远端文本时附带自有标记 `PiBot.ClipboardSync.OwnWrite.v1` 及上述排除标记。剪贴板被其他应用占用时做有界重试，单次写入失败不会让同步永久停止。
- **Linux 过滤与防回环**：仅监听常规 `CLIPBOARD`（绝不监听 `PRIMARY` 中键选择），读取前先检查 MIME / `TARGETS`，遇到 `x-kde-passwordManagerHint`、`ExcludeClipboardContentFromMonitorProcessing`、`org.nspasteboard.ConcealedType` / `TransientType` / `AutoGeneratedType`、`application/x-password`、`text/x-password` 及文件复制 MIME（`x-special/gnome-copied-files`、`application/x-kde-cutselection`）直接跳过；写入时附带自有 MIME `application/x-pibot-clipboard-sync`。对剪贴板管理器剥离标记后重新提供的相同文本，用短时内容指纹拦截回传；刚接收的同一段文本在约 2 秒内再次复制也可能被跳过。监听异常中断会停止报告在线，并尝试重新连接原生显示会话。

### Android（ARM64 / x86_64）

- **后台接收**：默认进程 `ClipboardSyncController` 调用独立 JNI 库 `libpibot_clipboard_sync.so`，依托客户端前台服务 `BotClientService` 维持 WSS 链路并自动将远端文本写入系统剪贴板（写入时附带自有标记 `EXTRA_OWN_SYNC`、label `pibot-clipboard-sync` 与 `ClipDescription.EXTRA_IS_SENSITIVE`，在 Android 13+ 抑制系统明文预览）。
- **手动发送回退（默认路径）**：受 Android 10+ 后台读取剪贴板限制，默认处于 `manual` 模式——仅当 `:tauri_ui` 的真实 `Activity` 处于前台且拥有窗口焦点时，用户点「立即发送（`sendNow`）」由 Kotlin 原生读取系统剪贴板并经私有同 UID 桥 `clipboardSyncSend` 送至默认进程加密发出（不向 WebView 回传正文；只提取现成的 `Item.getText()`，忽略伴随 HTML，不用 `coerceToText`；多条目、URI/Intent、敏感标记、自有标记以及 Shower 的 `pibot` 剪贴板仍不发送）。
- **系统分享与划词**：在其他应用的分享面板或文本选择菜单选择「发送到 PiBot 同步组」，在 PiBot 的原生确认框确认后发送已分享的纯文本。无需 Shizuku，也不读取或改写本机剪贴板；PiBot 客户端需正在运行、同步开关开启且已在线。
- **可选 Shizuku 自动发送**：在系统里给 PiBot 授予 Shizuku 权限后，还要在剪贴板设置里单独同意后台自动发送。仅在设备允许后台读取、用户已解锁且客户端链路在线时监听；授权撤销、Shizuku 不可用或系统不支持时退回「自动接收＋手动发送」。不使用无障碍权限、透明窗口或系统日志绕过。
- **生命周期边界（无额外承诺）**：不承诺设备重启/开机后自动拉起剪贴板同步（也不承诺 Shizuku 服务在重启后存活），不承诺在用户暂停/退出客户端前台服务（`BotClientService` 停止）或系统强杀后继续后台收发。本地开关与组码使用独立 AndroidKeyStore alias（`clipboard_sync.state.v1`）以 AES-GCM 写入不参与备份的 `clipboard_sync_state_v1.json`，无明文回退。

## 构建、CI 触发与版本策略

- 桌面发行包和 Android APK 的现有 CI 没有路径过滤，`clipboard-sync/` 变更不需要新增触发规则。APK 包含两个 ABI 对应的 `libpibot_clipboard_sync.so`，构建校验 16 KiB ELF 段对齐并合并 Rust 依赖许可证。
- 三个 `clipboard-sync/` 内部 Rust crate 均不对外发布，版本与产品独立。应用版本仍以根目录 `package.json` 和 `gradle.properties` 为准。
